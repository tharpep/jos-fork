Exercise 4:

Q1: What is the purpose of having an individual handler function for 
each exception/interrupt? (i.e., if all exceptions/interrupts were delivered 
to the same handler, what feature that exists in the current implementation
could not be provided?)

A1: Individual handler functions are needed because there are some exceptions that 
push an error code to the stack, while others don't. Each handler needs to account for 
the difference so the trap frame has a uniform layout. If all exceptions were
delivered to the same handler, there would be no way to know the trap number
or if an error code was pushed.


Q2: Did you have to do anything to make the user/softint program behave
correctly? The grade script expects it to produce a general protection fault
(trap 13), but softint's code says int $14. Why should this produce interrupt
vector 13? What happens if the kernel actually allows softint's int $14
instruction to invoke the kernel's page fault handler (which is interrupt
vector 14)?

A2: No, we did not have to do anything special. The int $14 instruction
triggers a general protection fault (trap 13) instead of a page fault 
because the IDT entry for interrupt 14 has DPL 0, meaning only the kernel
is allowed to invoke it. When user-mode code tries to issue int $14, the 
processor checks the DPL of the gate descriptor and sees that CPL (3) > DPL (0),
so it raises a general protection fault instead. If the kernel allowed user
code to invoke the page fault handler directly (by setting DPL=3 on the page
fault IDT entry), a user program could trigger fake page faults, potentially
confusing the kernel's memory management and breaking isolation between user 
environments.
